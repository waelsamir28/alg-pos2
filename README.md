# نظام إدارة المكتبة — POS

واجهة عربية للمبيعات والمشتريات والمرتجعات والمخزون والعملاء والموردين والخزنة والأرباح، مع حفظ محلي ومزامنة اختيارية إلى Neon عبر Vercel.

## التشغيل المحلي

يتطلب Node.js 22 أو أحدث:

```sh
npm ci
npm run dev
```

افتح `http://localhost:3000`. لا تفتح `index.html` مباشرة عبر `file://`؛ ملفات JavaScript تستخدم ES modules وتحتاج خادم HTTP.

تعمل الشاشات والحفظ المحلي بدون قاعدة بيانات. يظهر الاتصال بالسحابة كغير مفعل حتى تُضبط المزامنة. لا يُنشئ خادم المعاينة بيانات وهمية أو بديلاً سحابياً وهمياً. الجهاز الجديد لا يحتوي على مبيعات أو رصيد خزنة افتراضي.

## المزامنة على Vercel

1. أضف `DATABASE_URL` الخاص بقاعدة Neon في **Settings → Environment Variables** على Vercel.
2. ولّد مفتاحاً عشوائياً طويلاً (32 حرفاً على الأقل)، مثلاً باستخدام `openssl rand -hex 32`، وضعه في متغير الخادم `SYNC_TOKEN`.
3. أعد نشر المشروع بعد إضافة المتغيرات.
4. في شاشة **إعدادات البرنامج** أدخل نفس المفتاح في **مفتاح المزامنة** واضغط حفظ الإعدادات. يمكن تفعيل **تذكّر كلمة مرور المزامنة على هذا الجهاز** لتجنب إدخالها مرة أخرى؛ عند إيقافه يبقى المفتاح في الجلسة الحالية فقط.
5. على الجهاز الذي يحتوي البيانات الصحيحة، اضغط رفع البيانات. على الأجهزة الأخرى اضغط سحب البيانات.

`DATABASE_URL` و`SYNC_TOKEN` متغير خادم فقط: لا تضعهما في `app.js` أو `index.html` أو المستودع. عند تفعيل التذكر يُخزن مفتاح واجهة المزامنة في تخزين المتصفح على الجهاز، ولا يدخل في النسخ الاحتياطية. لا تفعّل التذكر على جهاز مشترك، وأزل بيانات الموقع عند الحاجة.

يمكن للمدير إضافة حسابات كاشير ومخزن من **الإعدادات → الموظفون والصلاحيات**، وتبديل المستخدم من شارة اسم المستخدم أعلى الشاشة. الحسابات وسجل النشاط محفوظة محلياً في المتصفح فقط، ولا تدخل في النسخ الاحتياطية أو المزامنة السحابية؛ يجب إعدادها على كل جهاز. هذه الصلاحيات وقفل الشاشة قيود تشغيلية في الواجهة وليست حماية أمنية للخادم أو من مستخدم لديه وصول مباشر إلى المتصفح والتخزين المحلي. غيّر الرقم السري الافتراضي للمدير قبل الاستخدام.

من **إعدادات البرنامج** يمكنك تفعيل أحد ثمانية ثيمات (كلاسيكي أخضر، ثلاثة ثيمات Vista، ثلاثة ثيمات Windows 11، والوضع الليلي). كل ثيم يعيد تلوين الهيدر والقائمة الجانبية والأزرار والجداول والحقول مع حالات Hover وضغط واضحة، ويمكن ضبط لون الواجهة الأساسي أو استعادته بزر واحد. يتوفر أيضاً زر الوضع الليلي في الشريط العلوي. الصفحة الرئيسية تعرض ملخصاً بيانياً للمبيعات لآخر سبعة أيام وتنبيهات النواقص والأرصدة والمزامنة، مع قائمة جانبية قابلة للطي ومجموعات أزرار منظمة. الواجهة متجاوبة للهواتف، وتدعم تصغير النوافذ العائمة وتكبيرها واستعادتها.

عند غياب المفتاح أو عدم صحته ترفض المزامنة. لم تعد المزامنة متاحة للعامة بدون مصادقة. يجب نشر الواجهة و`api/sync.js` معاً؛ الواجهة الجديدة تتوقع رد المزامنة الذي يتضمن رقم النسخة.

### الحماية من فقدان البيانات

- الحفظ المحلي يسبق المزامنة؛ فشل الشبكة لا يلغي المعاملة المحلية.
- الحفظ التلقائي للسحابة مؤجل ومتسلسل، ولا يبدأ قبل ربط النسخة المحلية بالسحابة يدوياً.
- تحديث السحابة مشروط برقم النسخة (`revision`) داخل جملة SQL واحدة. الأجهزة المتزامنة لا تستبدل تعديلات بعضها بصمت؛ يظهر تعارض بدلاً من ذلك.
- السحب والاستعادة يؤكدان قبل استبدال البيانات المحلية. الاستعادة لا ترفع البيانات تلقائياً.
- عند تعارض النسخ، صدّر نسخة محلية أولاً، ثم اسحب السحابة للمقارنة. لا يوجد دمج محاسبي تلقائي؛ رفع نسخة قديمة فوق الأحدث قد يحذف فواتير، لذلك يتطلب تأكيداً صريحاً عند الربط الأول.
- ملف محلي تالف لا يُستبدل تلقائياً. تتيح الواجهة تنزيل الأصل قبل استعادة نسخة سليمة.
- الحد الأقصى لحمولة المزامنة أو الاستعادة 4 ميجابايت. إذا تجاوزتها البيانات، يلزم تصميم تخزين أرشيفي منفصل بدلاً من رفعها ككتلة واحدة.

الجدول الحالي `pos_store` يخزن نسخة كاملة في الصف `id=1`. الإصلاح يضيف `revision` تلقائياً مع الحفاظ على البيانات الموجودة. هذا تصميم مناسب للبيانات الصغيرة، وليس دمجاً متعدد المستخدمين على مستوى كل فاتورة.

## المحاسبة والمخزون

- الخصم الإضافي يوزع على بنود الفاتورة، وتُحسب الأرباح من صافي البيع الفعلي.
- تكلفة المبيعات والمرتجعات تُحفظ وقت العملية؛ تعديل سعر الشراء لاحقاً لا يعيد كتابة تكلفة الفواتير القديمة.
- الشراء يحدّث متوسط تكلفة الصنف مرجحاً بالكمية، بما في ذلك أثر الخصومات. مرتجع المشتريات لا يغير متوسط التكلفة.
- المرتجع يرتبط بفاتورة أصلية، ويستخدم تكلفتها وصافي أسعارها، ولا يتجاوز الكمية غير المرتجعة سابقاً.
- البيع ومرتجع المشتريات لا يسمحان برصيد سالب. القيود تُفحص قبل حفظ المعاملة بأكملها.
- عرض السعر لا يغير المخزون أو الخزنة أو الأرصدة. تحويله للبيع يحول دون تكرار التحويل.
- المدفوع لا يتجاوز الصافي. الآجل والجزئي يتطلبان حساباً مسجلاً.
- كشف الحساب يتضمن الرصيد الافتتاحي والرصيد الجاري؛ مرتجع المبيعات يخفض رصيد العميل، ومرتجع المشتريات يخفض رصيد المورد.
- تقرير الصنف الواحد يعرض ربح ذلك الصنف بدون خصم مصروفات المنشأة كلها منه. المصروفات تظهر في تقرير كل الأصناف.
- التواريخ المستخدمة في القيود والتقارير هي التواريخ المحلية للجهاز، لا تاريخ UTC.

## النسخ الاحتياطي والطباعة

- **تحميل نسخة احتياطية (JSON)** يشمل بيانات البرنامج كاملة. احتفظ بنسخ خارج المتصفح؛ مسح بيانات الموقع يمسح الحفظ المحلي.
- الاستعادة تتحقق من البنية والأرقام والمعرّفات والمبالغ وأنواع الحركات قبل الاستبدال.
- CSV يهرب علامات الاقتباس ويمنع صيغاً تنفيذية في الخلايا النصية.
- الباركود حقيقي بنمط Code 39 للأرقام والحروف الإنجليزية والرموز المدعومة، حتى 40 حرفاً. ليست كل رموز EAN/UPC مدعومة؛ تحقق من قارئ الباركود لديك قبل طباعة كمية كبيرة.
- الطباعة A5 تستخدم قيم الحقول الحالية وتحذف أزرار الإجراءات. إعداد الورق في نافذة الطباعة قد يتجاوز مقاس CSS حسب المتصفح والطابعة.
- يمكن طباعة الفاتورة على طابعة حرارية بعرض 80 مم أو 58 مم من الإعدادات. اضبط حجم الورق نفسه في تعريف الطابعة والمتصفح.
- اختصارات الفاتورة: F2 لبدء البيع والتركيز على الباركود، Enter لإضافة الصنف، F4 للحفظ، Ctrl+Enter للحفظ والطباعة الحرارية، F6 لتعليق الفاتورة مؤقتاً، وF8 لاستعادتها. المسودات المعلقة محلية على الجهاز فقط.

## التثبيت كتطبيق (PWA) والتخصيص

- البرنامج قابل للتثبيت من المتصفح كتطبيق سطح مكتب/موبايل: `manifest.webmanifest` + `sw.js` (تحميل مسبق للهيكل الأساسي حتى يفتح بدون إنترنت) + أيقونات PNG مولّدة محلياً عبر `node scripts/make-icons.js`.
- زر ⬇️ في الهيدر (أو زر «تثبيت البرنامج على الجهاز» في الإعدادات) يستخدم `beforeinstallprompt` أو يعرض خطوات التثبيت اليدوية عند عدم توفرها. المزامنة (`/api/`) لا تُخزَّن مؤقتاً أبداً حتى لا تُعرض بيانات سحابية قديمة.
- **الإعدادات ← استوديو التخصيص الكامل**: قوالب جاهزة، ألوان الهيدر وشريط العنوان والقائمة الجانبية والأزرار والحدود والخلفية، رفع صورة للهيدر وأخرى لخلفية البرنامج، دوران الحواف (أو حواف حادة)، سماكة الحدود، الظل، ارتفاع الهيدر وحجم الخط. يُحفظ كل ذلك محلياً في `*_DESIGN`.
- كل ثيم يعيد تشكيل البرنامج كاملاً وليس اللون فقط: ثيمات Vista تستخدم أسطحاً زجاجية بحواف دائرية وبرّاقة داخلية، وثيمات Windows 11 تستخدم أسلوب Fluent (حدود رقيقة وظلال خفيفة وتدرجات هادئة)، والكلاسيكي يبقى مسطحاً، والليلي بلوحة داكنة.
- خط **Cairo** مضمّن محلياً في `fonts/` (رخصة OFL) فلا يعتمد البرنامج على أي شبكة خارجية.
- الهيدر يحتوي اسم المتجر والهاتف تحته فقط، مع مؤشر المزامنة (يومض، وأخضر عند تفعيل المزامنة) والساعة وأزرار الوضع الليلي والتثبيت والمستخدم.

## شاشة البداية وتسجيل الدخول

- شاشة بداية احترافية: مربع بحواف دائرية عليه شعار واسم المكتبة، وشريط تحميل متحرك بنسبة مئوية، ثم خانات الدخول (قائمة الموظف + الرقم السري) كلها بحواف دائرية.
- **الإعدادات ← التخصيص ← الصور** فيها زر «خلفية شاشة البداية» مع شريط لضبط وضوحها، وتُحفظ محلياً.
- بعد الدخول الصحيح تظهر **رسالة ترحيب عائمة** باسم المستخدم وتحيتها حسب الوقت، وتُغلق تلقائياً بعد 3 ثوانٍ.
- نتائج المزامنة (رفع/سحب/تعارض/فشل) تظهر في **نافذة صغيرة عائمة** بأزرارها الخاصة، والتنبيهات العادية في بطاقة صغيرة أسفل الشاشة.

## تصميم موحّد لكل الشاشات

- كل شاشة تبدأ بشريط عنوان كامل العرض بتدرج كحلي ← سماوي، وبعده شريط أدوات (تبويبات + بحث + الإجراء) ثم الجداول داخل إطار بشريط عنوان صغير.
- شاشة الأصناف صارت ثلاثة تبويبات: بيانات الصنف، الأسعار والربح، إجراءات وأدوات — مع شريط بحث دائم وعدّادات في شريط العنوان.
- شاشات المجموعات، الجرد، الملصقات، العملاء والموردين، سجل الفواتير، الخزنة، التقارير والإعدادات كلها بنفس النمط، ولكل شاشة عدّاداتها الخاصة في شريط العنوان.
- إعدادات النظام فيها شريط تنقل سريع بين أقسامها (المظهر، بيانات المنشأة، المزامنة، الموظفون).

## شاشة البيع (نمط الأشرطة)

- **شريط العنوان** أعلى الشاشة بتدرج كحلي ← سماوي: اسم العملية بخط كبير على اليمين، ومبدّل نوع العملية (مبيعات / مرتجع / مشتريات / عرض سعر) على اليسار.
- **شريط أدوات الفاتورة**: أزرار «تفاصيل الفاتورة، الخصم، العميل والحساب، ملاحظات وطباعة» على الجهة الشمال، وحقول التبويب المختار في الوسط. لا تُعرض كل الحقول دفعة واحدة، فتظل الشاشة مرتبة.
- **شريط الباركود**: خانة باركود مصغّرة بجانب خانة العدد (بأزرار − و+) وزر «بيع / إضافة» على نفس السطر.
- **المجموعات قائمة منسدلة**: اختيار مجموعة يعرض أصنافها كأزرار، مع بحث سريع وعدّاد للأصناف.
- **ملخص الفاتورة**: صف صغير (إجمالي البنود، الخصم، دفع بالمبلغ) ثم ثلاثة صناديق مرتفعة وملوّنة: الصافي المطلوب (أخضر)، المدفوع (أزرق)، المتبقي (كهرماني).
- **شريط أزرار الفاتورة** بالترتيب: حفظ ← حفظ وطباعة ← تعليق ← استعادة معلقة ← طباعة حرارية ← (تحويل العرض) ← تفريغ، بأزرار كبيرة وأيقونات مناسبة الحجم وألوان تحويم وضغط مختلفة.
- **شريط مفاتيح الوظائف** أسفل الشاشة: عشرة أزرار متساوية (F2–F11) في صف واحد — ومنها F7 لتفريغ الفاتورة.
- الشاشات العائمة تُفتح كبيرة بعرض البرنامج بالكامل، وزر التكبير في شريط النافذة يعيدها للحجم العادي. زر «طباعة الشاشة» أُزيل من شريط النوافذ، وتبقى أزرار طباعة التقارير داخل شاشاتها.

## الفحص

```sh
npm run check
npm test
npm audit
```

الاختبارات تستخدم Node وJSDOM لاختبار المنطق وواجهة DOM ومعالج API باستخدام عميل SQL بديل. لا تحتاج قاعدة بيانات حقيقية ولا تتصل بـNeon. اختبار النشر الفعلي والمزامنة بين جهازين يحتاج مشروع Neon وبيئة Vercel مضبوطتين.

## البنية

- `index.html`: الشاشات والتنسيق.
- `app.js`: التفاعلات والحفظ المحلي والمزامنة والطباعة.
- `lib/finance.js`: حسابات المال والخصومات والتكلفة.
- `lib/data.js`: التحقق من البيانات وتوافق النسخ القديمة.
- `lib/barcode.js`: توليد Code 39 محلياً.
- `api/sync.js`: دالة Vercel المصادق عليها والتحديث المشروط للنسخة.
- `scripts/dev-server.js`: خادم المعاينة المحلية، وليس بديلاً عن نشر Vercel.
- `manifest.webmanifest`, `sw.js`, `icon-*.png`: دعم التثبيت والعمل بدون إنترنت.
- `fonts/`: خط Cairo المضمّن محلياً.
- `scripts/make-icons.js`: توليد أيقونات PWA بدون مكتبات خارجية.
